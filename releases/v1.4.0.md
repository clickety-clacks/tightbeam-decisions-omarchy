# Tightbeam Decisions 1.4.0

A redesigned decision window built around one job: understand the request well
enough to rule on it. It also runs on Scottland as well as Hyprland.

## Changes

- **New decision window.** The question is restated in plain words at the top.
  Below it, a brief explains what happened and what the explainer recommends.
  Each ruling choice is a button in the body that says what choosing it causes,
  with the agent's own option word and a number key. When the choices scroll out
  of view, a compact strip of them docks above the ask box, so they never leave
  the screen. Very small windows keep just the question and the choices.
- **Keyboard ruling.** ↑↓ or a number arms a choice and Enter records it; a
  click still records directly. `/` focuses the ask box, Tab cycles body,
  choices and ask box.
- **Ask box** grows with what you type, up to two thirds of the window.
  Enter sends; Shift+Enter starts a new line.
- **Identifiers** (plan, request, assignment, work item) sit in a footer and
  copy with a click; in small windows they fold into an `IDs ▾` menu.
- **Original request** is one click away at the end of the body, verbatim.
- **Type and size.** Newsreader for the question and your own words, IBM Plex
  Sans for explanations, IBM Plex Mono for verbatim system text. The fonts are
  bundled (SIL OFL) and apply to decision windows only. Colors follow the
  Omarchy theme, light or dark. Windows open at 3:4.
- **One window per request.** Opening a request that is already open brings
  its window to you instead of opening a second. On Scottland a rail widget or
  a side window comes to the middle at full size; on Hyprland it is focused.
- **Settings (Ctrl+,)** is now an ordinary window you can move, instead of an
  overlay.
- **Scottland.** Compositor calls live in `bridge/compositor.js`, chosen from
  the session (Hyprland or Scottland). A finished reply in a window you are not
  using shows Scottland's attention halo instead of taking focus.
- **Fix:** decision windows could lose summaries, chat and the model picker
  when the window host started before the desktop exported `PATH`. Node now
  runs through `bridge/node.sh`, which reads the current `PATH` each time.

## Installation and upgrade

No new dependencies. Updating the plugin reloads the window host, which closes
open decision windows; reopen them from the bar. Coordinate upgrades with the
user.

## Verification

- Bridge tests pass (15 of 15), including the compositor backend tests.
- Every layout was exercised in a headless Scottland session with real input
  (clicks, keys, typing) on real requests at several window sizes and font
  scales, light and dark themes, including the docked choices, the growing ask
  box, presenting from a side zone and from a rail widget, and the attention
  halo.
- Used on osanwe (Scottland), including recording a ruling and the handled
  state.
- Not yet exercised on Hyprland.
