# Tightbeam Decisions 1.3.0

Pick the harness, model and thinking level from inside the plugin, see which
model version each Claude alias currently means, and tell decision-request
kinds apart at a glance. The bar and menu get a new flag mark.

## Changes

- Add agent settings to the scroll-motion screen (Ctrl+,): harness, model and
  thinking level, saved to `~/.config/omarchy/tightbeam-decisions-model.json`
  and shared by every window and both summarizers. Existing conversations keep
  their model until re-summarized.
- Show the current version behind Claude aliases in the picker, e.g.
  "Opus 5.5 (1M)" for `opus[1m]`. The harness is asked once per Claude Code
  release without sending a prompt; the plain label is shown if that fails.
- Label decision-request kinds by what they ask of you, with one icon used on
  the kind toggles, every row, and the decision window:
  󱜸 Agent questions (`operator`) and 󰗶 Substrate issues (`effort`).
  Substrate-issue rows read "Automatic check-in · nothing produced in N min".
- Replace the question-mark bar icon and the balance-scale header icon with a
  swallowtail flag, drawn as vector paths so it follows the theme colors and
  turns the accent color when a request is new.
- Split the bar button (`DecisionMenuIndicator.qml`) from the dropdown, which
  is renamed from `Panel.qml` to `DecisionMenu.qml`.

## Behavior change: tools are always approved

The chat now auto-approves every tool request from the harness, for all roles
and both providers. 1.2.0 asked for permission by default. Keep this in mind
before asking the chat to act on your behalf.

## Installation and upgrade

From the plugin directory, run:

```sh
npm ci --prefix bridge --ignore-scripts --omit=optional
```

Then restart the Omarchy shell (`omarchy restart shell`) so the bar picks up
the renamed entry point and new icon. Coordinate upgrades with the user:
writing live plugin QML can reload the window host and close open decision
windows.

To open the menu from a key, bind
`omarchy-shell shell toggle mike.tightbeam-decisions '{}'`.
