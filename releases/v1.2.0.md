# Tightbeam Decisions 1.2.0

Decision-request now owns its ACP integration and uses the system-installed
Codex or Claude harness. Ask is no longer a runtime dependency. Both the main
chat and parent/notes/choice summarizer use the package's pinned ACP adapters
and configurable models in `summarizers.json`.

## Changes

- Request native window attention when an assistant reply completes in an unfocused window.
- Keep standalone windows on the current theme and preserve their opening Tightbeam host configuration.
- Fix ruling-button dispatch and improve menu multi-selection and row descriptions.
- Allow steering during an active turn; add re-summarization and compact header summaries.
- Use serif user prompts and leave 2.5 lines above a submitted prompt.

## Installation and upgrade

Install and authenticate the system `codex` or `claude` executable separately.
From the plugin directory, run:

```sh
npm ci --prefix bridge --ignore-scripts --omit=optional
```

The optional `provider` in `summarizers.json` selects `codex` or `claude`;
otherwise Omarchy's default agent is used. Codex defaults to
`gpt-5.6-luna` with `xhigh` reasoning. Ask settings are no longer inherited.
The chat defaults to asking for tool permission. See README for configuration
and installation of the bundled `show-decision-request` skill.

Coordinate upgrades with the user: writing live plugin QML can reload the
window host and close open decision windows.

The responsive header/action-panel changes currently under development are
not included in this release.
